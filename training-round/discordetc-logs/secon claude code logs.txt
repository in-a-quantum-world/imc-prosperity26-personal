# Experiment: TrigramHash + SOTA stack

**Status: NOT YET RUN** | Target: beat 1.1147 BPB

## Hypothesis

The SOTA BigramHash hashes consecutive token pairs `(t-1, t)` into an embedding lookup that adds short-range context to residual stream. Extending to **trigrams `(t-2, t-1, t)`** provides an extra length-3 n-gram signal with **zero additional parameters** — both bigram and trigram hashes index into the same `3072 × 112` embedding table via a different hash function.

Expected gain: small but free. If the embedding table has capacity (it starts zero-initialized), the gradient update can carve out separate regions for bigram vs trigram lookup without collision pressure. The risk noted in the code is that it may slow embedding optimization.

## Changes vs SOTA (2026-03-25_ValCalib_GPTQ_XSA_BigramHash3072)

| Parameter | SOTA default | This experiment |
|-----------|-------------|-----------------|
| `TRIGRAM` | 0 (off) | **1 (on)** |
| All others | unchanged | unchanged |

**Zero parameter count change** — trigrams share the bigram embedding table. Artifact size should be identical to SOTA (~15.9 MB).

## Architecture

Same as SOTA (11L, 512d, GQA 8h/4kv, MLP 3×, XSA-all, BigramHash 3072×112, Full GPTQ, LZMA9) with trigram lookups added to the embedding forward pass:

```python
h = self.embed(bigram_hash(tokens)) + self.embed(trigram_hash(tokens))
```

`trigram_hash(t) = (36313*t[t] ^ 27191*t[t-1] ^ 51497*t[t-2]) % (vocab_size - 1)`

# Experiment: Value Residual Learning (VRL) + SOTA stack

**Status: NOT YET RUN** | Target: beat 1.1147 BPB

## Hypothesis

Each attention layer computes values `v = W_v @ x`, then discards them after attention. **Value Residual Learning (VRL)** keeps a running accumulator of raw values from the first layer (`v0`) and injects it into every subsequent layer via a sigmoid-gated skip connection:

```python
v = v + sigmoid(alpha) * v0   # alpha initialised to 0 → sigmoid(0) = 0.5
```

This lets every layer "remember" the raw token representation without going through N successive projections, which helps with long-range identity and reduces representational collapse in deep GQA models.

**Parameter cost**: 11 × 1 scalar `vrl_alpha` per attention layer = 11 float32 params ≈ negligible artifact impact.

| All others | unchanged | unchanged |

**Minimal parameter increase** (~44 bytes for 11 vrl_alpha scalars). Artifact size essentially unchanged.

## Architecture

Same as SOTA with VRL injection. In `CausalSelfAttention.forward`:
- Layer 0: `raw_v = v`, passed as `v0` to subsequent layers
- Layers 1-10: `v = v + sigmoid(vrl_alpha) * v0`

# Experiment: BigramHash 4096 × 112 (wider table)

**Status: NOT YET RUN** | Target: beat 1.1147 BPB

## Hypothesis

The SOTA uses a hash table of 3072 slots for bigram lookups. With a vocabulary of 1024 tokens, there are 1024² = 1,048,576 possible bigrams being hashed into 3072 buckets — a **341:1 collision ratio**. Widening the table to **4096 slots** reduces this to 256:1, potentially letting the model learn more fine-grained bigram associations.

The lineage for this setting: 1536 (PR #549) → 2048 (PR #609) → 3072 (SOTA this work) → **4096 (this experiment)**.

At 3072 the improvement over 2048 was meaningful. The question is whether 4096 pushes past the break-even point (extra artifact bytes vs accuracy gain) that was found for going wider past 3072.

# Experiment: Gated Attention + SOTA stack

**Status: NOT YET RUN** | Target: beat 1.1147 BPB

## Hypothesis

Standard scaled dot-product attention outputs the same magnitude regardless of input content. **Gated attention** adds a per-head sigmoid gate conditioned on the input, allowing the model to "zero out" irrelevant attention heads dynamically:

```python
gate = sigmoid(W_gate @ x)     # shape: (B, T, num_heads)
y = y * gate.unsqueeze(-1)     # scale each head's output
```

`W_gate` is `dim × num_heads` (512 × 8 = 4096 params per layer), initialised with bias=4.0 so `sigmoid(4.0) ≈ 0.98` — the gate starts near-open and trains to selectively suppress. This encourages **sparse, content-dependent** attention patterns at minimal cost.

**Parameter cost**: 11 layers × (512×8 + 8) = 11 × 4096 = 45,056 non-banked float32 params ≈ 176 KB in artifact (bf16). Small.

## Changes vs SOTA (2026-03-25_ValCalib_GPTQ_XSA_BigramHash3072)

| Parameter | SOTA default | This experiment |
|-----------|-------------|-----------------|
| `GATED_ATTENTION` | 0 (off) | **1 (on)** |
| All others | unchanged | unchanged |

## Interaction Notes

XSA (cross-position self-attention subtraction) runs *before* gating in the forward pass:
1. Flash Attention 3 → y
2. XSA subtraction on y
3. **Gating applied to y**

This means the gate modulates the XSA-corrected output, not the raw attention output. May compound or cancel XSA effect — worth watching.

What key techniques reduced NanoGPT's training time from 45 minutes to 90 seconds?

The training time for NanoGPT was reduced from 45 minutes down to under 90 seconds using 8 NVIDIA H100 GPUs, requiring under 400M tokens instead of the original 10B tokens to reach the target 3.28 validation loss
.
This massive improvement was driven by numerous algorithmic and system optimizations
. The key techniques include:
Modernized architectural upgrades: Replacing older components with Rotary embeddings, QK-Norm, and ReLU² activations
.
Optimizer advancements: Use of the Muon optimizer, alongside variations like NorMuon and the Polar Express implementation in Muon
.
Attention enhancements: Implementation of Flash Attention 3 with a long-short sliding window pattern and window size warmup using YaRN, paired head attention, extra embeddings mixed into the values in attention layers, and a sparse attention gate
.
Precision and numerical scaling: Utilizing FP8 matrix multiplication for the head, along with asymmetric rescale and softcap logits
.
Structural and residual modifications: Introducing skip connections from the embedding directly to every block as well as from block 3 to 6, paired with an exponential decay of the residual stream
.

How do scaling laws help determine the best compute budget allocation?

Scaling laws help determine the optimal allocation of a fixed compute budget by revealing predictable mathematical relationships between model performance (measured by cross-entropy loss) and key training variables
. Specifically, language model performance scales as a power-law with model size, dataset size, and the total amount of training compute
.
By mapping these equations, researchers discovered a critical insight for compute efficiency: larger models are significantly more sample-efficient
. Therefore, the most optimal way to allocate a compute budget is not to train a small model until it converges, but rather to train very large models on a relatively modest amount of data, stopping significantly before convergence
.
In practice, these laws allow developers to target specific optimization goals depending on their constraints. The recent model training challenges can be categorized by these scaling dynamics:
L(N) Optimization: Challenges like Parameter Golf fix the number of parameters (N) to find the lowest possible loss, entirely unconstrained by data or compute time
.
L(T) Optimization: Challenges like the NanoGPT Speedrun (which reduced training time to 90 seconds) optimize for the lowest time (T) required to hit a specific, constrained target loss
.
L(D) Optimization: Challenges like the NanoGPT Slowrun aim for the lowest possible loss given a strictly constrained dataset size (D)
.

What is the Muon optimizer and how does it work?

The Muon optimizer is an optimization algorithm that functions as a way to smooth out spectral steepest descent, offering a different set of memory and runtime tradeoffs compared to other second-order optimizers like Shampoo
. Originally developed through experimental pursuits in CIFAR-10 speedrunning, Muon was crucial to reducing the NanoGPT training time by acting as a highly efficient alternative to Adam
.
How it works: At its core, Muon relies on approximately orthogonalizing the gradient matrix
. Instead of using a computationally expensive Singular Value Decomposition (SVD) to orthogonalise the matrix—which would make the optimizer too slow to be useful—Muon relies on a specifically quintic (fifth-order) Newton-Schulz iteration
.
The key mechanics of its operation include:
Momentum integration: It applies Nesterov momentum inside the update step, and then applies the orthogonalization process after the momentum
.
Optimized polynomial coefficients: The quintic Newton-Schulz iteration uses non-convergent coefficients designed to maximize the slope at zero
. This minimizes the number of iterations required, as it rapidly converges to a range between 0.68 and 1.13, rather than slowly converging exactly to 1
.
Precision formatting: The Newton-Schulz iteration is run entirely in bfloat16 precision, which is much faster than the fp32 or fp64 precision often required by inverse-pth-root calculations in other optimizers
.
Key benefits for training: When applied to language model training setups like NanoGPT, Muon provides several distinct advantages:
Lower memory usage than the standard Adam optimizer
.
~1.5x better sample-efficiency
.
An incredibly low computational cost, adding less than 2% wallclock overhead to the training process
.

### What "Parameter Banking" means

Attention (Q, K, V, Out) and MLP (Up, Down) weights are stored in 3D banks `[n_layers, rows, cols]`. This lets Parallel Muon do a single fused reduce-scatter across all layers' gradients instead of one per layer, reducing communication overhead.

## Optimizer: Muon

**Muon** (Momentum + Orthogonalization) works by:
1. Applying Nesterov momentum to the gradient
2. Orthogonalizing via Newton-Schulz 5-step quintic iteration (coefficients a=3.4445, b=-4.7750, c=2.0315 chosen to maximize slope at zero — converges in 5 steps to range [0.68, 1.13] rather than to exactly 1)
3. Run entirely in **bfloat16** — ~2× faster than fp32 NS5
4. Adds <2% wallclock overhead vs Adam
5. ~1.5× better sample efficiency than Adam for matrices

**Parallel Muon** extends this to 8-GPU distributed training:
- Phase 1 (after backward): launch async reduce-scatter for all banks simultaneously (largest first)
- Phase 2: Adam steps on small non-banked params while RS is in-flight
- Phase 3: wait for each RS → local NS5 on shard → async all-gather

Non-banked params (biases, norms, VE, MTP heads, gating scalars) use Adam.

---

## Quantization Pipeline

Post-training, before artifact export:

1. **AR self-gen calibration**: model generates 64 sequences × 2048 tokens at temp=0.8 (fixed seed). These are used as calibration data — no val or train data accessed.
2. **Full Hessian GPTQ**: for each linear layer, compute H = X^T X from calibration activations. Quantize columns in order of increasing Hessian diagonal (columns that contribute most to activation norm last). Cholesky error compensation propagates quantization error to future columns.
3. **Selective ±1 pruning**: for each quantized weight w_q, try w_q ± 1. If reconstruction error decreases (measured against float activations), apply the ±1 change.
4. **int6 packing**: 6-bit storage for quantized weights.
5. **LZMA preset=9**: final lossless compression.
6. **MTP heads excluded**: `export_sd = {k: v for k, v in full_state_dict.items() if "mtp_heads" not in k}`

## Key Research Findings

### From Modded-NanoGPT speedrun

The speedrun reduced NanoGPT training time from 45 minutes to ~90 seconds using 8×H100s. Key techniques relevant to Parameter Golf:

- **MTP (Multi-Token Prediction)**: Auxiliary losses on t+1, t+2, ... provide 2-3× gradient signal with zero inference cost. MTP heads excluded from final artifact.
- **Muon optimizer**: ~1.5× better sample efficiency than Adam for matrix params. <2% wallclock overhead.
- **BigramHash + TrigramHash**: n-gram context embedded into residual stream. Bigram uses XOR hash of adjacent tokens.
- **SmearGate**: σ-gated 1-token look-back for positional mixing.
- **Value embeddings**: Low-rank token identity injected into attention values at late layers.
- **Flash Attention 3**: Hopper-specific warp-specialized kernels, required for full speed.
- **YaRN sliding window with warmup**: Longer context via RoPE scaling — not yet in our SOTA.
- **Paired head attention**: Not yet implemented.
- **"Backout"**: Single activation input for last 3 attention layers — not yet implemented.

### From scaling laws research

- Language model performance scales as a **power law** with model size (N), data (D), and compute (C).
- For a fixed compute budget: train **larger models** on **less data** (stop before convergence) — Chinchilla optimal.
- For Parameter Golf (fixed N ≤ 16MB): the constraint is artifact size, not training compute. Maximize use of the 10 minutes and spend artifact budget efficiently.
- Diminishing returns on bigram table size: 1536→2048→3072 showed clear gains. 3072→4096 is the next test.

| | Muon | Adam |
|--|------|------|
| Memory | Lower (no second moment for banked params) | Higher |

| Wallclock overhead | <2% | Baseline |
| Best for | 2D+ matrix params (QKV, MLP, embed) | Scalars, biases, 1D params |
| Mechanism | Orthogonalized gradient via Newton-Schulz | Adaptive moment estimation |

**Fix**: reduce `BIGRAM_DIM` to 104: `(4096 × 104 - 3072 × 112) × 2 = (425984 - 344064) × 2 = +163,840 bytes`. Safer.
Or use `BIGRAM_DIM=96`: `(4096×96 - 3072×112) × 2 = (393216 - 344064) × 2 = +98,304 bytes`. Clearly fits.
